# Token and cost strategy review

Reviewed October 27, 2026. This comparison covers published evidence beyond OpenAI. It informs the Codex setup in this directory; it does not prove savings in your own workspaces.

| Strategy | External evidence | Decision for this setup |
| --- | --- | --- |
| Short, relevant instructions and context loaded when needed | [Anthropic's context engineering guide](https://www.anthropic.com/research/effective-context-engineering-for-ai-agents) recommends a small set of useful context and retrieval during work. [GitHub's Copilot context guide](https://docs.github.com/en/copilot/concepts/prompting-and-context/context-management) shows that instructions, tool definitions, history, and tool output all occupy context. | **Keep.** Use a short override and read linked guidance only when a task needs it. Audit large tool output and MCP definitions. |
| One agent for routine coding; specialists for bounded work | [A controlled programming study](https://liang-y-yu.github.io/publication/2025-10-01-paper-title-number-10) found similar acceptance for single and multi-agent setups on 133 LeetCode tasks, with multi-agent generation taking four times as long. [Google's architecture guide](https://docs.cloud.google.com/architecture/choose-design-pattern-agentic-ai-system) recommends starting with one agent and notes coordinator and reviewer cost. | **Keep conditional routing.** Do not require a planner or reviewer for every change. Use an independent review when correctness, concurrency, data handling, or contracts warrant it. The programming study is narrower than repository work. |
| Smaller models for clearly scoped subtasks | [Anthropic's agent patterns](https://www.anthropic.com/research/building-effective-agents) describe routing easy work to smaller models. [Databricks' coding benchmark](https://www.databricks.com/blog/benchmarking-coding-agents-databricks-multi-million-line-codebase) found cheaper token rates can still mean higher total task cost when a model uses more tokens or fails more often. | **Test, do not assume.** Keep the low-cost explorer for concise file and symbol searches. Measure full-task cost and rework before expanding its use. |
| Large multi-agent orchestration | [Anthropic's research system](https://www.anthropic.com/research/multi-agent-research-system) improved broad research results, but reported much higher token use and noted coding is often less parallelizable. [Google](https://docs.cloud.google.com/architecture/choose-design-pattern-agentic-ai-system) also describes coordinator and synthesis overhead. | **Reserve for genuinely independent work.** The research win does not establish a coding cost win. |
| Optimize the harness and tool context | [Databricks](https://www.databricks.com/blog/benchmarking-coding-agents-databricks-multi-million-line-codebase) saw more than twice the cost for the same model and quality in some harness comparisons, driven partly by context size. [GitHub](https://docs.github.com/en/copilot/concepts/prompting-and-context/context-management) describes how tool output fills context. | **Audit next.** Enabled MCP servers may add context, but their token contribution has not been measured. Keep only tools needed for each workflow when practical. |
| Measure completed work and actual billing | [Stanford's coding-agent study](https://digitaleconomy.stanford.edu/publication/how-do-ai-agents-spend-your-money-analyzing-and-predicting-token-consumption-in-agentic-coding-tasks/) found large run-to-run token variation and weak correlation between extra tokens and accuracy. [OpenAI's speed guidance](https://learn.chatgpt.com/docs/agent-configuration/speed) shows Fast mode changes usage rates. | **Make this the gate.** Compare cost per accepted task, quality, repair time, and latency across repeated tasks. Verify the actual service tier and charges in the usage dashboard; local logs cannot settle them. |

## What the current pilot proves

The previous A/B answered one narrow question correctly with both setups. The shorter instruction setup used 34% less total input and 54% less uncached input on that task. It did not test a complete coding workflow or a specialist handoff. Weekly usage totals also mix different workloads and models, so they cannot establish the savings from this setup.

## Next comparison

Use a small set of real, repeatable tasks: a focused code search, a routine Go edit, and a change with a material review risk. For each strategy, record the task result, token and credit estimate across all agent calls, actual tier or charge when available, elapsed time, human repair time, and whether the result was accepted. Repeat enough to expose run-to-run variation. Keep a strategy only when its cost per accepted task improves without unacceptable quality loss.
